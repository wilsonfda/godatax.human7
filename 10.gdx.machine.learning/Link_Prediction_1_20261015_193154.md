## Method

- **Embeddings:** Neo4j GDS FastRP, 32 dimensions, over the catalog subgraph (variables, constructs, instruments, septenary levels, chakras, Five Ways, Virtology virtues, and their mapping edges) — 32 variable nodes, 7 level nodes, 33 virtue nodes.
- **Training set (level):** 18 real `MAPS_TO_LEVEL` positive edges (materialized from `GDX_PSY_SEPT_LEVEL_PSY_MAP`) + 18 sampled non-edges, Hadamard-product features, a logistic regression trained in-process (see this file's header for why the classifier runs here instead of via `gds.beta.pipeline.linkPrediction.predict` — a real platform bug in that step's relationship-endpoint write-back was found and worked around, not a design preference).
- **Training set (virtue):** 17 real `MAPS_TO_VIRTUE` positive edges (materialized from `GDX_VT_VARIABLE_VIRTUE_MAP`) + 17 sampled non-edges — same embeddings, features, and classifier design as the level task above, trained and scored independently (own positives, own sampled negatives; a variable can be unmapped on one target and mapped on the other).
- **Independent validation, level (GDS's own pipeline, same features, different code path):** AUCPR test=0.7500, validation avg=0.7500.
- **Independent validation, virtue (GDS's own pipeline, same features, different code path):** AUCPR test=0.7500, validation avg=0.7500.
- **Small-N caveat:** 18 positive examples across 7 levels and 17 positive examples across 33 virtues are both small training sets — several levels/virtues have only 1-3 (or 0) supporting examples. Treat every score below as a triage rank, not a confident classification (same caveat the design doc raises for the original 19-example baseline).
