# new_study_intake/

Working area for the `GDX_SKILL_NEW_STUDY` -> `GDX_SKILL_RECORD_NEW_STUDY` pipeline. Not used by
`GDX_SKILL_LOAD_RLT_MODEL_DB` (the `.sav`-based loader) at all.

One subfolder per new study/instrument onboarded through the skills, named after the study's slug:

```
new_study_intake/
  <slug>/
    intake.json                              -- written by GDX_SKILL_NEW_STUDY, the interview result
    01_new_study.sql                         -- generated by GDX_SKILL_RECORD_NEW_STUDY
    02_new_instrument_01_<instrument-slug>.sql
    02_new_instrument_02_<instrument-slug>.sql   -- one per instrument in intake.json
```

See `GDX_HUMAN/0.new.instrument/` for the full explanation of the process, and each skill's
`SKILL.md` (`0.new.instrument/.claude/skills/GDX_SKILL_NEW_STUDY/` and
`GDX_SKILL_RECORD_NEW_STUDY/`) for exactly what each file contains and how it is produced.

`intake.json` and the generated `.sql` are meant to be committed alongside the rest of this folder
once a study is genuinely onboarded (they document what was asked for and what was loaded, the
same way `samples.SQL/` documents the `.sav` load) — they are not build artifacts to gitignore.
